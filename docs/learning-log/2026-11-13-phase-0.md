# Day 1 — Phase 0: project skeleton

## Decisions and why

**Monorepo.** Agent core, backend, frontend and infra live together. A single
logical change (a tool definition, its API, its UI) would otherwise mean three
pull requests across three repositories. Polyrepo pays off when separate teams own
separate deploy cycles; solo it is pure overhead.

**`src/` layout rather than a flat package.** With a flat layout `import forge`
silently resolves to the *directory* instead of the installed package, so tests
pass locally and the package breaks once installed anywhere else. `src/` makes
that impossible: the package must be installed, so what is tested is what ships.

**`uv` with a committed lockfile.** `uv.lock` pins every transitive dependency to
an exact hash, so `uv sync` reproduces an identical environment on any machine.
This is what makes it possible to continue this work from a different computer.

**Config exclusively through `pydantic-settings`.** Every environment-dependent
value — the Ollama URL, model name, API keys — is read from the environment and
validated at startup. This is the mechanism that lets the same code run against
the office GPU or a cloud provider by changing one variable, and it is why the
provider abstraction in Phase 1 is cheap.

**`SecretStr` for API keys.** Prevents a key leaking into a log line or traceback
through `repr()`. There is a test asserting this.

**mypy `strict` from the first commit.** Retrofitting types onto an existing
codebase is miserable; starting strict costs almost nothing.

## A problem worth remembering

The first test file called `Settings(_env_file=None)` to avoid reading a developer's
`.env`. It works at runtime but fails mypy, because `_env_file` is not in the type
stubs. The honest fix was not a `type: ignore` — it was an autouse fixture that runs
every test in a clean temporary directory with all `FORGE_*` variables unset. Test
isolation was the actual requirement; `_env_file` was a shortcut around it.
